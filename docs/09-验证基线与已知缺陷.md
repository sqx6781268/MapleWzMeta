## 3. 图标覆盖（`imgdata/`）

```bash
find imgdata -name '*.img.png' | wc -l                                    # 28,504
./bin/maplewzmeta.exe stats | head -1                                     # 图标索引：28,503 个文件，28,307 个可用 ID
tot=0; for off in $(seq 0 500 56500); do
  tot=$((tot + $(curl -s "http://127.0.0.1:8080/api/items?limit=500&offset=$off" | grep -o '"icon":"' | wc -l)))
done; echo $tot                                                           # 22,165
```

| 指标 | 值 | 说明 |
|---|---|---|
| 磁盘图片 | 28,504 | `Character` 20,682 / `Npc` 7,465 / `Item` 357 |
| 进入索引的文件 | 28,503 | 1 个被拒：`01102488_.img.png`（词干含下划线，非纯数字） |
| 可用 ID | 28,307 | 同 ID 取优先级后去重；`Item`=357、`Character`=20,676、其他=7,274 |
| 物品行带图标 | 22,165（39.40%） | 其余 ID 属 Npc 等其他实体域 |

**串味提醒**：把索引 join 回物品行可得 22,162 行命中，其中 **1,578 行（7.1%）的图标其实来自 `Npc` 域**
（`Character` 20,278 / `Item` 306）——`Npc.wz` 的 ID 与物品 ID 重叠 1,806 个，`Mob.wz` 重叠 1,861 个，
`rankOf` 只保证装备图优先，挡不住"该 ID 没有装备图、于是拿 NPC 立绘顶上"。
取样：`00002003`、`00012000`、`09000001`。详见
[附录-实体与String.wz的关联](附录-实体与String.wz的关联.md) §6。

坑：`01102670 .img.png`（词干带**尾随空格**）能被索引，因为 `NormalizeID` 先 `TrimSpace`。
导出器偶发产生这类文件名，改 `Build` 的过滤时注意别把它们全丢掉。

## 4. 已知缺口（非缺陷）

| 缺口 | 数字 | 定性 |
|---|---|---|
| 缺名称 | 28,568 条，其中 Hair 15,234 + Face 9,555 占 87% | **不是导出范围问题**（旧结论已证伪）：其中 **22,691 条**（Hair 13,348 / Face 9,343）的名称其实就写在 `String.wz/Eqp.img.xml` 里，只是那些条目用 **5 位 ID**，被 `LooksLikeItemID` 的位数判据整批丢弃。真·导出缺口只有 **5,877 条**（Weapon 2,185 / Hair 1,886 / Accessory 407 / Cap 300 / Face 212 …），这 5,877 条在 `String.wz` 全部 20 张表的任意数字键里**一条都找不到**。详见 [附录-实体与String.wz的关联](附录-实体与String.wz的关联.md) §5 |
| 缺属性 | 4,733 条 | 只有 `String.wz` 名称、`Item.wz`/`Character.wz` 无对应 ID。其中 **461 条是宠物道具**（`0500xxxx`）：`Item.wz/Pet` 的文件名直接就是 7 位 ID，而"根名即 ID"的特判只对 `Character.wz` 开（`internal/extract/extract.go:117`），整目录属性漏抽——**这是缺陷不是缺口**。剩下很大一块其实是**怪物/NPC/技能名称**，见 §5 |
| 第二语言 | 未配置 | `wz-zh-CN/` 只导出 51 个 XML，且其 `String.wz` 与 `wz/String.wz` **md5 相同**，当独立 locale 扫入只会得到一个只有名称的残缺域 |

多语言**能力**已就绪并用真实导出验证过：两个 locale 分别扫 `String.wz` 与 `Item.wz` 时，
`zh-CN` 得 28,084 条全名称零属性、`en` 得 6,461 条零名称全属性，互不覆盖。
等真正拿到另一语言的完整导出，只需在 `locales` 追加一项后 `scan`，无需改代码。

## 5. 已知缺陷：名称侧跨实体表污染（**未修，代码现状**）

### 现象

`scan` 的分流判据只是"相对路径以 `String.wz` 开头 → 名称侧"（`internal/scan/scan.go:240`），
于是 `String.wz` 目录下**每一张表**都按物品名称入库。其中三张属别的实体域：

| 文本表 | 带 `name` 的 7/8 位 ID 条目 | ID 实际含义 | 补零后落入的 item 语义 |
|---|---|---|---|
| `String.wz/Mob.img.xml` | 2,002 | 怪物 ID（`1110100` 绿蘑菇） | `0111xxxx` = 戒指号段 |
| `String.wz/Npc.img.xml` | 1,803 | NPC ID | `0100xxxx`/`0101xxxx` = 帽子/饰品号段 |
| `String.wz/Skill.img.xml` | 542（7 位 360 + **8 位 182**） | 技能 ID | 与 `Etc`/`Consume`/`Cash` 号段大面积重叠 |

合计 **4,347 条**，占该语言域名称条目（28,260）的 **15.4%**。怪物表里 6 位 ID（`100100` 蜗牛）
被 `LooksLikeItemID` 正确挡掉了，漏进来的恰好是 7/8 位那批。
Npc 表 7,404 个键里只有 1,842 个带 `name`（其余是 `n0`/`d0` 对话），所以污染面被天然限制在 1,803。

**污染面是 100%**：三张表的键补零后与库内 56,264 个物品 ID 逐一比对，2,002 / 1,803 / 542 **全部命中**——
物品 ID 空间被各实体域整体复用，不存在"错开号段"的保护。
`Map`/`MonsterBook`/`PetDialog`/`ToolTipHelp` 四张表也用数字键，但它们**没有 `name` 子节点**，
被"名称必需"判据挡住，不贡献污染。取数与逐表贡献见
[附录-实体与String.wz的关联](附录-实体与String.wz的关联.md) §1、§4。

### 实测证据（`data/mia.db`，`zh-CN`）

| 物品 ID | 库里名称 | 名称真实来源 | 应得名称 |
|---|---|---|---|
| `01110100` | 绿蘑菇（分类空、无属性） | Mob 表 | 该号段是 Ring，此条本不该存在 |
| `04000000` | 集中术 | Skill 表 | `Etc.img.xml` 的"蓝色蜗牛壳" |
| `01002004` | 褐色战斗头盔 | Eqp 表（**这例没被污染**） | `Npc.img.xml` 的"明珠港星级出租车" |

第三个例子说明赢家不固定：同一 ID 被多张表命中时，落库结果取决于**并发解析的完成到达顺序**
（`internal/scan/scan.go:140` 起的多协程 fan-out + `:160` 单消费者按到达顺序攒批），
而非文件名字典序。本机三次重扫这三个 ID 恰好稳定，但**不保证可复现**，文件数/机器负载一变即可能翻转。

统计侧的可观测症状：名称条目 28,262 → 唯一 ID 27,696，**566 个 ID 被跨表重复写名**；
`仅有名称`（4,733）里有相当一部分根本不是物品，而是怪物/NPC/技能。

### 复现命令

```bash
# 只扫 String.wz 到一个临时库，观察名称条目数与 27,696 的唯一数之差
printf '{"db":"tmp/a.db","workers":8,"icons":{"enabled":false},"locales":[{"lang":"zh-CN","wz":"D:/ASM/MapleWzMeta/wz","sources":["String.wz"]}]}' > tmp/cfg.json
./bin/maplewzmeta.exe scan -config tmp/cfg.json      # 写入名称条目 28262；物品 27696 全为"有名称零属性"
./bin/maplewzmeta.exe query -id 01110100             # 绿蘑菇
# 各表识别面与实际贡献（Git Bash 下 perl 正则别写 `(?!…)`，`!` 会被改写成 `\` 而报错）
for f in Mob Npc Skill Eqp Etc Consume Cash Ins Pet; do
  printf '%-10s 7/8位键=%-7s 其中带name=%s\n' $f \
    "$(grep -o '<imgdir name=\"[0-9]\{7,8\}\"' wz/String.wz/$f.img.xml | wc -l)" \
    "$(grep -o '<string name=\"name\"' wz/String.wz/$f.img.xml | wc -l)"
done
# 交集（既 7/8 位又带 name）= 该表对名称侧的真实贡献，用附录 §8 的 tmp/wzrel*.mjs 脚本复刻
```

### 修复方向（择一，均未实施）

| 方案 | 做法 | 代价 |
|---|---|---|
| A 表名白名单（**推荐**） | 名称侧只认 `Cash/Consume/Eqp/Etc/Ins/Pet` 六张物品文本表，其余 `String.wz` 文件跳过 | 需重扫；未来新增物品文本表要同步白名单 |
| B 按 ID 段过滤 | 名称侧只认物品号段（02xx/03xx/04xx/05xx/09xx + 装备 01xx/000x） | 规则易随版本漂移，且挡不住同段冲突。**附录 §4 已证 ID 空间被实体域整体复用，本方案不可靠** |
| C 冲突显式化 | `item` 加 `name_source` 列，多表命中时记录并告警，不静默覆盖 | 不消除污染，只是可观测 |
| D 放宽位数（**与 A 配套**） | 名称侧允许 5 位纯数字（`String/Eqp` 的 Hair、Face），补零后入库 | 单独用会引入 `Mob` 6 位、`Npc` 3~5 位的新污染，必须先做 A |

配套要做：让落库顺序**与到达顺序无关**（例如每批按 `path` 排序后再喂 `PutNames`），
否则白名单之外仍会有"先入者 vs 后入者"的抖动。
另有独立一处缺陷：`Item.wz/Pet` 的 461 个宠物道具属性整批漏抽（"根名即 ID"特判只对 `Character.wz` 开），
把该特判扩到任意源即可，现成的 `extract.RootID` 未被调用。
修完后本节的 **4,347 条污染**与 566 个重复 ID 应归零，`仅有名称` 数会显著下降——**这是预期内的下降，别当成回归**；
同时做完 A+D 后 `名称+属性齐全` 应从 22,963 涨到约 **45,654**（+22,691），这两组新基线待重扫后回填本页。

## 6. 端到端验收清单

改完前端 / 存储 / 配置后按此顺序过一遍（浏览器验证不可省略——历史上 URL 拼接 bug 只有真浏览器里才暴露）：

1. `go test ./... -count=1` 全绿；
2. `maplewzmeta stats` —— 图标索引规模 > 0、语言域数字与本页一致；
3. `maplewzmeta scan` —— 全部跳过未变；
4. `maplewzmeta serve`，日志出现「语言：… ，图标：开」；
5. `curl /api/langs`、`/api/items?cat=Accessory`（看 `icon` 字段）、`/api/meta`（看 `categories[].label` 与 `attrs[].label`）、`/img/<id>.png`（200 + `image/png`）；
6. 条件叠加抽样核对，命中数须与库内分布自洽：
   `cat=Weapon&min=reqLevel=100&max=reqLevel=150` → 1,915、`like=islot=wp` → 5,492、`has=incPAD` → 7,419、
   `attr=cash=1&min=reqLevel=120` → **0**（商城武器一律 `reqLevel=0`，这是数据事实不是过滤失效）；
7. 真实浏览器：语言下拉、图标列渲染（`naturalWidth > 0`）、左侧栏分类显示 `武器（Weapon）` 且搜索框能过滤、
   属性条件可增删（含手输未收录键、`存在` 时值框禁用）、点行出右上浮层、×／遮罩／Esc 三种关闭、
   **点上一页/下一页不得滚动或弹出详情**、`icons.enabled=false` 时图标列整列消失。

> 前端改动必须 `go build -o bin/maplewzmeta.exe ./cmd/maplewzmeta` 重编再重启：页面走 `go:embed`，
> 改 `static/index.html` 不重编二进制是不会生效的。

## 7. 辅助命令

| 命令 | 用途 |
|---|---|
| `cmd/wzstats` | 全量解析但不落库，输出规模/耗时/类型统计，用来验证解析内核 |
