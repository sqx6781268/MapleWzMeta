| `scripts-zh-CN/` | 外部数据 | 同套脚本的中文版，2,272 个文件；**当前管线未消费** |
| `docs/` | 文档 | 本目录 |

## 3. 三种文件形态（决定抽取层级）

```
形态 A ── 单文件 = 单实体，根 imgdir 名即 ID
   Character.wz/Cap/01002936.img.xml      （根 name="01002936.img"，info 在根下）
   Character.wz/00002000.img.xml          （根级直挂，无子目录 → 分类为空）
   Mob.wz/0000021.img.xml   Npc.wz/0002000.img.xml

形态 B ── 单文件 = 多实体，根下按 ID 分条
   Item.wz/Etc/0430.img.xml               （根 name="0430.img"，子节点为 8 位 ID）
   String.wz/Cash.img.xml                 （根下直接挂 7 位 ID）
   String.wz/Etc.img.xml                  （根 → "Etc" → 7 位 ID，多一层）
   String.wz/Eqp.img.xml                  （根 → "Eqp" → 部位 → 7 位 ID，多两层）

形态 C ── 纯素材/层级树，节点名不是数字 ID
   Map.wz/Map/Map0/000000000.img.xml      （9 位）
   Base.wz/smap.img.xml   UI.wz/Login.img.xml
```

**因此识别 ID 不依赖固定层数**，规则是"名字为 7~8 位纯数字的 `imgdir` 即实体节点"，
见 `internal/extract/extract.go:38` `LooksLikeItemID`。

## 7. `imgdata/`（图标导出）

布局：`imgdata/<Wz 名>/<可选类别>/<ID>.img.png`，共 **28,504 个 PNG**。

| 目录 | 文件数 | 说明 |
|---|---|---|
| `imgdata/Character/` | 20,682 | 14 个部位子目录，**缺 `Hair`、`Face`、`Afterimage`** |
| `imgdata/Npc/` | 7,465 | 无类别层，`0000700.img.png` 直接平铺 |
| `imgdata/Item/` | 357 | **只有 `Pet`**，缺 `Etc`/`Consume`/`Cash` 等 |

- 索引规则：ID 先零填充到 8 位；**同号冲突按 `Item` > `Character` > 其他** 取优先级
  （`internal/icons/icons.go:81` `rankOf`）。
- 图标与语言无关 → 不落库，只在 `serve`/`stats` 时内存建索引。
- 上述缺口是**导出范围**问题，不是索引缺陷；补导后无需改代码。


文件名以实体 ID 命名（`1002000.js`）。内容为 Nashorn 风格 JS，通过 `npc.sendNext` 等回调驱动对话。
**当前 Go 管线完全不读取它们**——属"脚本域"，若要做 NPC 对话检索需另立实体表，不要塞进 `item`。
注意顶层模板文件名含空格，脚本处理时需引号。

## 9. 例外与脏目录

- `wz/UI.wz/CashShop.imgX.xml` —— 后缀是 `.imgX.xml` 而非 `.img.xml`；按 `*.xml` 能收到，
  但根名不合法则解析失败，会记进 `wz_file.status='failed'`。
- `wz/Mob.wz/QuestCountGroup/` —— 10 个 7 位 ID 文件，与怪物立绘同层但语义不同。
- `wz/Npc.wz`、`wz/Reactor.wz`、`wz/Morph.wz` 等包**没有类别子目录**，全部 `*.img.xml` 平铺在包根。
- `NPT_exception.img.xml`（`Etc.wz`）文件名带下划线，无特殊处理需求。
