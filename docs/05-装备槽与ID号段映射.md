# 05 · 装备槽（islot）与 ID 号段映射

> 结论来自 2026-09-21 的实测：每个 8 位号段取**代表文件**提取 `info/islot`，
> 中文名称样本取自 `wz/String.wz/Eqp.img.xml`。
> **判类权威是 `info/islot`，目录名与 ID 号段都可能骗人**（陷阱见 §4）。

## 4. 已确认的目录交叉陷阱

| 陷阱 | 影响 | 应对 |
|---|---|---|
| `Accessory` 内含 2 个 `Cp` 帽子 | 按目录判类会错分类 | 以 `islot` 为准 |
| `Longcoat`、`Shoes` 各有 1 个 0100 段文件 | 同上 | 同上 |
| `Shield` 与 `Accessory` 都有 0119 段 | 号段不唯一 | 需结合 `islot` + 目录 |
| `Weapon/0134`、`0135` 的 islot 实为 `Si`（盾） | 目录名骗人 | 以 `islot` 为准 |
| `PetEquip`、部分 `TamingMob`(0198)、部分 `Weapon`(0145/0146) **无 islot** | 判类失败 | 回落到 ID 号段 |
| `Face` 的 0004 段与 `Hair` 重叠，且混入 18 个 `Hr` | 发型/脸型混淆 | 先看 `islot`，再按目录消歧 |

## 5. 其他常用 info 字段

| 字段 | 类型 | 含义 |
|---|---|---|
| `islot` | string | 装备槽（本表） |
| `vslot` | string | 可选槽位串，如 `CpH1H5` = 帽子槽 + 人类头饰 1 + 5 |
| `reqLevel` / `reqSTR` / `reqDEX` / `reqINT` / `reqLUK` / `reqJob` | int | 需求 |
| `incPAD` / `incMAD` / `incPDD` / `incMDD` / `incMMP` / `attack` | int | 属性加成 |
| `speed` / `jump` / `tuc` / `price` / `slotMax` | int | 速度 / 跳跃 / 可修次数 / 单价 / 堆叠上限 |
| `cash` / `serial` / `tradeBlock` / `only` / `notSale` / `undead` | int(0/1) | 标志位，检索用 `attr=cash=1` |
| `icon` / `iconRaw` | canvas | 图标尺寸与 `origin` 偏移（非图片本体） |

## 6. 重新统计时的取数方法

- **不要**逐文件 `head -c | grep` 循环 45k 文件：需 40 分钟以上，曾中途放弃。
- 改为**每个号段取 1 个代表文件**提 `islot`，约 70 次读取即可覆盖全表。
- 按名称反查类别：`grep -oP '(?<=<imgdir name=")\d{7}(?=">)'`。
  `Eqp` 表内 ID 是 **7 位、无前导零**，写成 8 位模式会全部匹配不到。
- 代码侧统计走 `bin/maplewzmeta.exe stats`（分类 Top12）或
  `go run ./cmd/wzstats -root ./wz -out wzstats.json`，见 [09-验证基线与已知缺陷](09-验证基线与已知缺陷.md)。
