# 06 · 数据模型与存储规则

库：`data/mia.db`（SQLite，WAL 模式）。实现全部在 `internal/store/store.go`。

## 1. 建库参数

```go
sql.Open("sqlite", path+"?_pragma=busy_timeout(10000)&_pragma=journal_mode(WAL)&_pragma=synchronous(NORMAL)")
d.SetMaxOpenConns(1)   // 单写多读，避免 SQLITE_BUSY
```

- 驱动：`modernc.org/sqlite`（**纯 Go，无 cgo**，本机没有 gcc）。
- `Open` 会自动 `MkdirAll` 父目录（`internal/store/store.go:104`）。
- 每次操作套 30 秒 `context.WithTimeout`（`internal/store/store.go:228`）。

## 2. 表结构（建表语句见 `internal/store/store.go:63`）

### `item` —— 关联后的物品主表

```sql
CREATE TABLE item (
  lang       TEXT NOT NULL,      -- 语言域，如 zh-CN
  id         TEXT NOT NULL,      -- 8 位零填充字符串，前导零有意义
  name       TEXT NOT NULL DEFAULT '',
  descr      TEXT NOT NULL DEFAULT '',
  category   TEXT NOT NULL DEFAULT '',
  info       TEXT NOT NULL DEFAULT '{}',   -- JSON 对象（map[string]string）
  has_name   INTEGER NOT NULL DEFAULT 0,
  has_info   INTEGER NOT NULL DEFAULT 0,
  updated_at INTEGER NOT NULL,   -- Unix 秒
  PRIMARY KEY (lang, id)
);
CREATE INDEX idx_item_name ON item(lang, name);
CREATE INDEX idx_item_cat  ON item(lang, category);
```

`info` 恒为 `map[string]string` 序列化结果，**没有嵌套 JSON**：嵌套结构在扁平化时就变成了
带点号的键（`icon.origin.x`）。因此 Go 侧反序列化成 `map[string]string` 是安全的，
失败即报错"物品 X 的 info 不是合法 JSON"（`internal/store/store.go:505`）。

`has_name` / `has_info` 是**独立事实位**，不等于"name 非空"：它们记录"这一侧是否真的写入过"，
用于统计覆盖度（`Stats` 里 `SUM(has_name*has_info)` 即"齐全"数）。

### `wz_file` —— 增量指纹表

```sql
CREATE TABLE wz_file (
  lang TEXT NOT NULL, path TEXT NOT NULL,   -- path 相对 wz 根，正斜杠
  size INTEGER NOT NULL, mtime INTEGER NOT NULL,
  status TEXT NOT NULL,                     -- ok / failed
  err TEXT NOT NULL DEFAULT '',
  repaired INTEGER NOT NULL DEFAULT 0,      -- 补了多少个截断标签
  rows INTEGER NOT NULL DEFAULT 0,          -- 该文件贡献的条目数
  scanned_at INTEGER NOT NULL,
  PRIMARY KEY (lang, path)
);
```

指纹判定在 `Pending`（`internal/store/store.go:233`）：**没有记录，或 `size` 变了，或 `mtime` 变了** → 需要重解。
失败记录同样入库，便于排查与定向重跑（`status='failed'` + `err` 原因）。

### `scan_run` —— 扫描历史

```sql
CREATE TABLE scan_run (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  lang TEXT NOT NULL DEFAULT '',
  started_at INTEGER NOT NULL, finished_at INTEGER,
  total INTEGER NOT NULL DEFAULT 0, parsed INTEGER NOT NULL DEFAULT 0,
  failed INTEGER NOT NULL DEFAULT 0, note TEXT NOT NULL DEFAULT ''   -- note = 参与扫描的 sources
);
```

`StartRun` 在解析前插一行拿 `runID`，`FinishRun` 回填收尾。用于回答"上次扫描跑了多久、处理了多少"。

## 3. 写入规则（UPSERT 语义）

| 方法 | 冲突动作 | 关键点 |
|---|---|---|
| `SaveFiles` | `ON CONFLICT(lang,path) DO UPDATE` 全字段刷新 | 一个事务内 prepared stmt 循环 |
| `PutNames` | 只更新名称侧；`name`/`descr` **非空才覆盖**；`category` **库内为空才填**；`has_name=1` | 名称 trim 后为空的条目跳过且不计数 |
| `PutInfos` | `info` 先读旧值 **按 key 合并** 再整体写回；`category` 同上；`has_info=1` | `len(Info)==0` 的条目跳过 |

三条设计意图：

1. **两侧互不覆盖**——`Item.wz` 后到不会抹掉 `String.wz` 已写的名字，反之亦然。
2. **空值不覆盖非空**——增量重跑时，某个文件导出残缺也不会把已有好数据清空。
3. **info 累积**——同一 ID 从多处补属性会合并（`mergeInfo`，`internal/store/store.go:388`；
   旧 JSON 解析失败时退化成空 map，即"用新值覆盖坏数据"而不是整条放弃）。

`DeleteMissing`（`internal/store/store.go:636`）在某语言域内删除磁盘上已不存在的 `wz_file` 记录，
返回删除数。**只删指纹，不删 `item`**：物品数据会保留，直到重新扫描时被新数据覆盖。

## 4. 旧库迁移（v1 无 `lang` 列 → v2）

`Open` 时自动执行 `migrateLegacy`（`internal/store/store.go:156`）：

```
对 item / wz_file 各做一遍：
  若表存在且无 lang 列：
    DROP INDEX idx_item_name; DROP INDEX idx_item_cat;   ← 必须先删，否则改名后同名索引挡住新表建索引
    ALTER TABLE t RENAME TO t_v1;
    执行 schema 建新表;
    INSERT OR IGNORE INTO t(lang, ...) SELECT 'zh-CN', ... FROM t_v1;
    DROP TABLE t_v1;
若 scan_run 存在且无 lang 列： ALTER TABLE ADD COLUMN lang TEXT NOT NULL DEFAULT ''
```

回填语言固定为 `LegacyLang = "zh-CN"`（`internal/store/store.go:26`），依据是"现有数据实测来自中文导出包"。

## 5. 检索条件构造（`Query.clauses`）

`internal/store/store.go:678`，全部走参数绑定，**不拼接用户输入进 SQL 文本**：

| 字段 | 生成条件 | 规则 |
|---|---|---|
| `Lang` | `lang = ?` | 必填，永远是第一个条件 |
| `ID` | `id = ?` | 精确，不补零 |
| `IDPrefix` | `(id >= ? AND id < ?) OR (id >= ? AND id < ?)` | 前缀 < 8 位时**同时**查 `P*` 与 `0P*`；上界用 `prefixUpper` 逐字节 +1，不用 `LIKE` 以便走主键 |
| `Name` | `name LIKE '%X%'` | 模糊 |
| `Category` | `category = ?` | 精确 |
| `HasName` / `HasInfo` | `has_name = ?` | 三态：`nil` 不过滤 |
| `Wants` | `json_extract(info, '$."k"') = ?` | 只支持等值 |
| `GTE` | `CAST(COALESCE(json_extract(info,'$."k"'),'0') AS INTEGER) >= ?` | 数值下界，缺字段按 0 |

**JSON 路径必须加双引号**：`jsonPath`（`internal/store/store.go:674`）把键包成 `$."icon.width"`，
并对 `"` 与 `\` 做转义。原因：真实键里有点（`icon.origin.x` 会被当成嵌套路径）和 `@`（`@indent`）。

`OrderBy` 走白名单（`id` / `name` / `category`，非法值回落 `id`），方向由 `Desc` 决定；
`Limit` 归一到 `1..500`，缺省 50（`internal/store/store.go:437`）。

## 6. 统计口径

| 指标 | 定义 | SQL |
|---|---|---|
| `items` | 该语言域物品总数 | `COUNT(*)` |
| `named` | 有名称 | `SUM(has_name)` |
| `withInfo` | 有属性 | `SUM(has_info)` |
| `complete` | **齐全** | `SUM(has_name * has_info)` |
| `files` / `failed` | 指纹数 / 失败数 | `COUNT(*)` / `SUM(status='failed')` |
| `lastRunUnix` | 最近一次扫描开始时间 | `MAX(started_at)` |
| `categories` | Top12 分类，空分类显示为 `(未分类)` | `COALESCE(NULLIF(category,''),'(未分类)')` |
| `langs` | 各语言域规模，按物品数降序 | `GROUP BY lang` |

## 7. 已知限制

1. **无全文检索**：`name LIKE '%X%'` 不走索引，27k 行级别无感，若扩到全实体域需另议。
2. **`Wants` 只支持等值**，`GTE` 只支持单键下界（HTTP 侧 `min` 参数覆盖为单条）。
3. **`info` 无类型**：全是字符串，数值比较靠 `CAST`。
4. **`DeleteMissing` 不清理孤儿 `item` 行**：删掉某语言的数据源后，物品行会残留，需手工
   `DELETE FROM item WHERE lang=?` 或另写清理。
5. 单写连接（`SetMaxOpenConns(1)`）意味着**并发扫描多个语言时互相排队**，`scan` 已经是逐语言串行调用。
